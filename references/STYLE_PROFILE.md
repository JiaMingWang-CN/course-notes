# 微课风格规划模板

> 本文件是设计建议，不代表已经观看或分析任何课程。仅在生成微课时读取。
> 将本课程记录保存到交付章节的 `references/STYLE_PROFILE.md`；不要把课程特定信息写回技能安装目录。

## 1. 证据与复用范围

每门课程只建立一次基础记录，章节可补充必要差异。最多选取 2–3 节代表课；不要逐节重复分析。

```markdown
# <课程名称> 微课风格记录
- 来源：<BV号/URL/本地资料>
- 适用范围：<课程/章节>
- 可用材料：<字幕/音频/实际观看的视频>
- 分析日期：<实际日期>
- 样本：<P、标题、时间范围；未采样则写未采样>
- 已观察到的特征：<附样本定位>
- 未核实项：<如配色、镜头、语速>
- 本次设计选择：<明确与原片观察区分>
```

| 可用资料 | 可以归纳 | 不可据此声称 |
|---|---|---|
| 仅字幕 | 知识组织、例题顺序、措辞 | 原片配色、镜头、音色、实测语速 |
| 音频 | 实际听到的节奏、停顿与发音 | 原片画面与布局 |
| 视频 | 实际观看片段内的视听特征 | 未观看部分或全课程一致性 |
| 无样本 | 下述默认设计建议 | 已完成抽样、讲师采用了这些风格 |

样本可按概念课、实现课、算法推演课挑选，但不得预填虚构 P 号或观察结论。既有记录只有在来源与范围一致时才能复用。

## 2. 教学结构

优先服务理解与复习，不使用“从不考证明”“必考”“10 秒必解”等未经证实的承诺。

建议安排：

1. **目标与条件**：说明要解决的问题、前置知识与适用范围。
2. **核心推演**：围绕一个代表例子展示状态变化；清楚标出变量和下标约定。
3. **易错反例**：展示失败条件及原因，不只闪烁警报。
4. **回顾与自检**：总结关键结论，给一道标注来源或“自编”的小题。

以 3–5 分钟为目标，根据实际口播字数、推演和停顿分配时长；不得把估算称为实测。复杂小节可拆成多个片段，不能删除保证结论成立的条件。

公式速记应同时保留通式、变量含义与边界。例如卡特兰数表只在题目满足相应计数模型时适用，不能脱离条件直接套值。

## 3. 制作文档一致性

| 资产 | 必要内容 |
|---|---|
| `BRIEF.md` | 学习目标、受众、来源、范围、不遗漏的事实 |
| `TREATMENT.md` | 设计选择、画面层次、主题、交互与降级方案 |
| `SCRIPT.md` | 可朗读台词、公式读法、必要停顿、画面提示 |
| `STORYBOARD.md` | 连续场景编号、预计起止时间、画面状态、对应台词 |

四份文档与笔记保持术语、例子、答案一致。预计总时长应与分镜合计一致；未实际播放时不得标为“音画同步已验证”。

本地生成器输出的是模板，不会自动读取风格记录。生成后需人工/主代理落实设计要求并修正失效的相对链接。

## 4. 视觉与交互建议

### 主题

优先采用用户明确偏好，其次已有画像，缺省使用 `cyberpunk`。内置主题名称：

- `cyberpunk`：深色背景、冷色强调。
- `academic`：浅色纸感、清晰文字层次。
- `brutalist`：粗线条、高对比。
- `glassmorphism`：半透明面板；保持文本可读性。
- `classic_blue`：蓝白配色、减少装饰。

主题改变不应改变算法语义；成功/警告/错误不能仅靠颜色区分，应辅以文字或图标。不得依据学校名自动推断审美偏好。

### 交互目标

- 播放、暂停、跳转状态明确；显示时间采用等宽数字，避免抖动。
- 按钮可经键盘操作，并有可见焦点；窄屏文字可换行，不遮挡主要操作。
- 动画用于表达数据和指针变化，不用装饰动效掩盖逻辑；尊重减少动画的偏好。
- 仅在沙盘模型与本课一致时启用交互；栈、队列、KMP 等必须明确初始状态、下标约定和非法操作。
- 无匹配沙盘时使用静态步骤图或分镜，不用其他算法模板冒充。
- 语音不可用时仍能阅读完整台词；不承诺所有浏览器都有同一中文音色。
- 外部资源依赖、离线能力与运行兼容性以实际文件和检查结果为准，不默认宣称零依赖或全面兼容。

以上是制作目标，不是现有生成器已实现或已测试的保证。

## 5. 交付状态

记录实际完成情况，避免把计划当结果：

- 内容：已核对 / 待核实（列出项目）。
- 制作文档：已生成 / 缺失。
- HTML：已生成 / 未生成 / 存在已知限制。
- 浏览器审查：通过 / 失败 / 未运行（原因）。
- 视频文件：只有实际生成后才列出；HTML 与分镜不等于 MP4。

用户明确要求不测试时，停止于静态内容核对，不运行浏览器或其他测试，并标记“未运行”。
